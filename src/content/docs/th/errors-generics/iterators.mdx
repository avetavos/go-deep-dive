## ทำไมต้องมี iterator?

ก่อน Go 1.23 function ที่ผลิตลำดับข้อมูลมีทางเลือกที่ไม่สวยอยู่สามทาง: สร้างแล้วคืน slice ทั้งก้อน (allocate ทุกอย่างตั้งแต่แรก), ส่ง channel ออกมา (ต้องเปิด goroutine และช้า) หรือคิด type `Next()` ของตัวเองที่ `range` ไม่รู้จัก Go 1.23 เพิ่ม **range-over-func**: `for` วนซ้ำบน function ที่มีรูปแบบเฉพาะได้ และ standard library ได้ package `iter` มาตั้งชื่อรูปแบบเหล่านั้น

ผลลัพธ์คือลำดับข้อมูลแบบ lazy ที่ไม่ allocate และใช้กับ syntax ของ loop ที่คุณรู้จักอยู่แล้ว

## `iter.Seq` และ `iter.Seq2`

package `iter` นิยาม generic function type ไว้สองแบบ:

```go
package iter

type Seq[V any] func(yield func(V) bool)
type Seq2[K, V any] func(yield func(K, V) bool)
```

iterator คือ function ที่รับ callback ชื่อ `yield` มันเรียก `yield` หนึ่งครั้งต่อ element; `yield` คืน `false` เมื่อผู้ใช้ต้องการหยุด และ iterator **ต้อง** return ทันทีในกรณีนั้น `Seq2` yield เป็นคู่ — index กับ value หรือ key กับ value — ล้อกับ `range` แบบสองตัวแปร

## การเขียน push iterator

นี่คือ counter ที่ yield `0..n-1` และหยุดก่อนจบเมื่อถูกขอ:

```go
func Count(n int) iter.Seq[int] {
    return func(yield func(int) bool) {
        for i := 0; i < n; i++ {
            if !yield(i) {
                return // consumer broke out of the loop
            }
        }
    }
}

for v := range Count(5) {
    if v == 3 {
        break // yield returns false inside Count, which returns
    }
    fmt.Println(v)
}
```

`break`, `return` และ `continue` ใน loop body ทำงานตามที่คาดทุกอย่าง: compiler แปลง body ให้เป็น function `yield` และแปลง control flow ให้เอง iterator เห็นแค่ `yield` คืน `false`

เพราะลำดับถูกผลิตตามความต้องการ `Count(1_000_000_000)` จึงไม่มีต้นทุนจนกว่าจะเริ่มวน — และถ้าหยุดหลังสามตัว ก็ผลิตแค่สามตัว

## Iterator บน type ของคุณเอง

รูปแบบ idiomatic คือ method ชื่อ `All`, `Keys`, `Values` หรือทำนองนั้น ที่คืน iterator แทน slice:

```go
type List[T any] struct{ items []T }

func (l *List[T]) All() iter.Seq2[int, T] {
    return func(yield func(int, T) bool) {
        for i, v := range l.items {
            if !yield(i, v) {
                return
            }
        }
    }
}

for i, v := range list.All() {
    fmt.Println(i, v)
}
```

caller ไม่ต้องแตะ backing slice และคุณเปลี่ยน representation ทีหลังได้อิสระ — linked list, database cursor, HTTP API แบบแบ่งหน้า — โดย loop ไม่ต้องเปลี่ยนเลย

## Standard library พูดภาษา iterator

ตั้งแต่ Go 1.23 package `slices` และ `maps` (ส่วน `strings`/`bytes` ตั้งแต่ Go 1.24) ทั้ง **ผลิต** และ **ใช้** iterator:

```go
import ("maps"; "slices"; "strings")

// consume: turn an iterator into a slice
evens := slices.Collect(filter(Count(10), isEven))   // []int
keys  := slices.Sorted(maps.Keys(m))                  // sorted keys, one line

// produce: iterate without copying
for i, v := range slices.All(xs)    { /* index, value */ }
for v := range slices.Values(xs)    { /* value only */ }
for k, v := range maps.All(m)       { /* key, value */ }

// strings (Go 1.24): lazy splitting
for line := range strings.Lines(text)          { /* each line, newline kept */ }
for part := range strings.SplitSeq(csv, ",")   { /* no []string allocated */ }
```

`slices.Collect`, `slices.Sorted`, `slices.SortedFunc`, `maps.Collect` และ `maps.Insert` คือสะพานกลับสู่ข้อมูลจริง ส่วน `strings.SplitSeq` และ `strings.FieldsSeq` คือฝาแฝดแบบ lazy ของ `Split` และ `Fields`

`filter` เล็ก ๆ ไว้อ้างอิง — combinator แบบนี้ประกอบกันได้เป็นธรรมชาติ:

```go
func filter[T any](seq iter.Seq[T], keep func(T) bool) iter.Seq[T] {
    return func(yield func(T) bool) {
        for v := range seq {
            if keep(v) && !yield(v) {
                return
            }
        }
    }
}
```

## Pull iterator

range-over-func เป็นโมเดลแบบ **push**: ฝั่งผู้ผลิตเป็นคนขับ ส่วน loop body ของผู้ใช้เป็น callback เมื่อต้องดึงทีละ element เอง — เช่น merge ลำดับที่ sort แล้วสองชุด — `iter.Pull` แปลง push iterator ให้เป็นคู่ `next()`/`stop()`:

```go
next, stop := iter.Pull(Count(3))
defer stop()
v, ok := next() // 0, true
```

`iter.Pull` ใช้ coroutine อยู่ข้างใน จึงช้ากว่า `range` ธรรมดา ใช้เฉพาะเมื่อจำเป็นต้องได้รูปแบบ pull จริง ๆ

## แนวทางการออกแบบ

- **คืน slice เมื่อข้อมูลเป็น slice อยู่แล้ว** และมีขนาดเล็ก iterator ไม่ได้เพิ่มอะไรตรงนั้น
- **คืน iterator** เมื่อลำดับมีขนาดใหญ่ ไม่มีที่สิ้นสุด ผลิตแพง มี I/O อยู่ข้างหลัง หรือเมื่อต้องการซ่อน representation
- **เคารพ `yield == false` เสมอ** iterator ที่ยังเรียก `yield` ต่อหลังจากมันคืน `false` จะ panic
- **ตั้งชื่อ accessor ว่า `All`, `Keys`, `Values`, `Backward`** ให้ตรงกับ standard library
- iterator เป็น function ธรรมดา: ไม่ได้ปลอดภัยต่อ goroutine โดยอัตโนมัติ และถือทุกอย่างที่ closure จับไว้
