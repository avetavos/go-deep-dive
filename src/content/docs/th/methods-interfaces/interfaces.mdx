## Interface คืออะไร?

**Interface** คือชุดของ method signature ที่มีชื่อ type ใดที่มี methods ทั้งหมดนั้นจะตอบสนอง interface — โดยไม่ต้องบอกอย่างชัดเจน

```go
type Shape interface {
    Area()      float64
    Perimeter() float64
}
```

type ใดที่มี method `Area() float64` และ `Perimeter() float64` จะตอบสนอง `Shape` โดยอัตโนมัติ

## Implicit satisfaction — ไม่มี `implements`

นี่คือคุณสมบัติที่กำหนดตัวตน interfaces ของ Go เปรียบเทียบ:

| ภาษา | วิธีประกาศการตอบสนอง |
|------|----------------------|
| Java / C# | `class Circle implements Shape` |
| Go | แค่มี methods ที่ถูกต้อง |

ผลลัพธ์คือโค้ดที่ *decoupled* type ใน package `geometry` สามารถตอบสนอง interface ใน package `renderer` โดยที่ไม่มี package ใดรู้จักอีก package ทำให้ Go interfaces compose ข้าม package boundaries ได้โดยไม่มี import dependency บน interface definition

## Small interfaces

standard library ของ Go สร้างบน interfaces เล็ก ๆ ที่มีจุดโฟกัส:

```go
type Reader interface { Read(p []byte) (n int, err error) }
type Writer interface { Write(p []byte) (n int, err error) }
type Stringer interface { String() string }
```

คำสอนของ Go: *"ยิ่ง interface ใหญ่ abstraction ยิ่งอ่อนแอ"* interface สอง methods ถูกตอบสนองโดย types จำนวนมากกว่า interface สิบ methods อย่างมาก ทำให้ reuse ได้มากกว่าอย่างมหาศาล

## Empty interface — `any`

Interface ที่ไม่มี method ถูกตอบสนองโดยทุก type ตั้งแต่ Go 1.18 มี alias ว่า `any`:

```go
var v any = 42
v = "hello"
v = []int{1, 2, 3}
```

ใช้ `any` อย่างประหยัด — เพราะสละ type safety กรณีใช้งานปกติ: generic containers (ก่อนที่ Go จะมี generics), JSON unmarshalling รูปร่างที่ไม่รู้จัก, และ function logging แบบ variadic

## Accept interfaces, return structs

แนวทาง Go ที่ idiomatic:

- **Function parameters** ควรเป็น interfaces — รับ type กว้างที่สุดที่ครอบคลุมสิ่งที่คุณเรียกจริง
- **Return values** ควรเป็น concrete structs — caller ได้รับ API เต็มของ type จริง; พวกเขา narrow เองได้

```go
// Good: accepts an interface, returns a concrete type
func NewReader(rd io.Reader) *bufio.Reader { ... }
```

export const interfacesCode = `package main

import (

\t"math"

type Shape interface {
\tArea()      float64
\tPerimeter() float64

type Circle struct {
\tRadius float64
}

\treturn math.Pi * c.Radius * c.Radius
}

func (c Circle) Perimeter() float64 {
\treturn 2 * math.Pi * c.Radius
}

type Rect struct {
\tW, H float64
}

func (r Rect) Area() float64      { return r.W * r.H }
func (r Rect) Perimeter() float64 { return 2 * (r.W + r.H) }

func describe(s Shape) {
\tfmt.Printf("area=%.2f perimeter=%.2f\\n", s.Area(), s.Perimeter())
}

func main() {
\tshapes := []Shape{
\t\tCircle{Radius: 5},
\t\tRect{W: 4, H: 3},
\t}
\tfor _, s := range shapes {
\t\tdescribe(s)
\t}
}`;

## Runtime Behavior

```text
interface value คือ 2 words:

iface
 ├─ *itab  →  ┌──────────────────────┐
 │            │ type: Circle         │
 │            │ methods: [Area,      │
 │            │          Perimeter]  │
 │            └──────────────────────┘
 └─ data   →  Circle{Radius: 5}

dynamic dispatch:
  shape.Area()
    ↓
  itab.fun[0](data)  ← indirect call
    ↓
  Circle.Area(data)
```

คุณตรวจสอบว่า type หนึ่งตอบสนอง interface ได้ตั้งแต่ compile time โดยไม่ต้องสร้าง value เลย ด้วย blank assignment:

```go
var _ Shape = (*Circle)(nil)
```

บรรทัดนี้ compile ผ่านก็ต่อเมื่อ `*Circle` มีทุก method ที่ `Shape` ต้องการ ไม่มีต้นทุนตอน runtime และจับ method ที่ขาดหรือสะกดผิดได้ทันทีตอนเขียนโค้ด แทนที่จะไปเจอตอนเรียกใช้ครั้งแรก

## ข้อแลกเปลี่ยน

| สิ่งที่ได้ | ประโยชน์ | ต้นทุน |
|---------|---------|------|
| implicit satisfaction | decoupled, no import dependency | ยากต่อการ discover ว่า type ใด implement interface ใด |
| small interface (1-2 methods) | composable, implement ง่าย | อาจต้องใช้หลาย interface ร่วมกัน |
| any / empty interface | รับ type ใดก็ได้ | สูญเสีย type safety ทั้งหมด |
| dynamic dispatch | flexibility | ต้นทุนจริง: indirect call (~1–3 ns) + เสีย inlining + ค่าอาจ escape ไป heap เมื่อ box |

## ความเข้าใจผิดที่พบบ่อย

- **interface ฟรี** — interface เพิ่ม indirection 1 ชั้นและ dynamic dispatch overhead
- **nil interface และ interface ที่เก็บ nil pointer เป็นเหมือนกัน** — nil interface คือ (nil, nil), interface ที่เก็บ nil pointer คือ (*T, nil) ซึ่งไม่เท่ากัน
- **ยิ่ง interface มี method มาก ยิ่งดี** — Go idiom: "the bigger the interface, the weaker the abstraction"
- **implicit satisfaction แปลว่า duck typing** — Go ตรวจสอบ interface ตอน compile ไม่ใช่ runtime

> 💡 ตัวอย่างจากของจริง
>
> **io.Reader** (1 method): http.Body, os.File, bytes.Buffer, strings.Reader ล้วน implement — composable ทั่ว ecosystem โดยไม่มี import dependency
>
> **Kubernetes** ใช้ interface `runtime.Object` (`k8s.io/apimachinery/pkg/runtime`) ให้ทุก Kubernetes resource ทำงานกับ generic controller ได้ — decoupling ผ่าน small interface

<Callout title="Interfaces ตอบสนองโดยนัย">
ทั้ง `Circle` และ `Rect` ไม่เคยกล่าวถึง `Shape` ทั้งคู่ตอบสนองเพราะมี `Area()` และ `Perimeter()` ที่มี signatures ถูกต้อง นั่นหมายความว่าคุณสามารถนิยาม interface *หลัง* types ที่ตอบสนอง interface นั้น — types เหล่านั้นไม่ต้องเปลี่ยนเลย การตอบสนอง interface แบบย้อนหลังเป็นหนึ่งในเครื่องมือ refactoring ที่ทรงพลังที่สุดของ Go
</Callout>
