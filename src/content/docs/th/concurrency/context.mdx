## context.Context คืออะไร?

`context.Context` เป็น standard interface ที่ส่งต่อ:

- **Cancellation signal** — goroutine สามารถตรวจสอบ `ctx.Done()` เพื่อรู้ว่าควรหยุดทำงาน
- **Deadline หรือ timeout** ที่เป็น optional — งานถูก cancel อัตโนมัติเมื่อถึงเวลา
- **Request-scoped key/value pairs** — metadata ขนาดเล็กเช่น request ID หรือ auth token

Package context แก้ปัญหาที่เป็นรูปธรรม: เมื่อ server request ถูก cancel (user ปิด browser, upstream timeout) goroutines ที่รันสำหรับ request นั้นจะรู้ได้อย่างไรว่าควรหยุด? การส่ง `context.Context` เป็น argument แรกให้ทุก I/O function คือคำตอบมาตรฐานของ Go

## การสร้าง Contexts

```go
// Root contexts — ไม่มี cancellation
context.Background()   // root ระดับบนสุด ใช้ใน main หรือ test setup
context.TODO()         // placeholder เมื่อยังไม่แน่ใจจะใช้ context ไหน

// Derived contexts — เพิ่ม cancellation/timeout บน parent
ctx, cancel := context.WithCancel(parent)
ctx, cancel := context.WithTimeout(parent, 5*time.Second)
ctx, cancel := context.WithDeadline(parent, time.Now().Add(5*time.Second))
ctx2       := context.WithValue(parent, key, value)
```

Derived contexts สร้าง tree การ cancel parent จะ cancel ลูกทั้งหมดอัตโนมัติ

## Cancellation Contract

เมื่อเรียก `context.WithCancel` หรือ `context.WithTimeout` คุณได้รับสองค่า: derived context และ `cancel` function คุณ **ต้อง** เรียก `cancel()` เมื่องานเสร็จ — แม้ context จะหมดอายุตามธรรมชาติ ถ้าไม่เรียก parent context จะถือ reference ถึง child context จนกว่าจะ cancel parent ด้วย ซึ่งทำให้ leak ทรัพยากร

```go
ctx, cancel := context.WithCancel(context.Background())
defer cancel() // always
```

## ฟัง Cancellation

ใน goroutine `ctx.Done()` return channel ที่ถูกปิดเมื่อ context ถูก cancel หรือ timeout ใช้ `select` เพื่อรวมกับงานจริง:

```go
select {
case result := <-workCh:
    return result, nil
case <-ctx.Done():
    return "", ctx.Err() // context.Canceled หรือ context.DeadlineExceeded
}
```

## context.WithValue

`context.WithValue` แนบคู่ key/value เข้ากับ context ใช้เฉพาะกับข้อมูลที่เป็น request-scoped และข้ามขอบเขต API เท่านั้น (request ID, auth token) **อย่า**ใช้มันเป็นกลไกทั่วไปสำหรับส่งผ่าน parameter — ค่าพวกนั้นควรอยู่ใน function argument แทน

เพื่อหลีกเลี่ยง key ชนกับ package อื่น ให้ใช้ type ที่เป็น unexported และเป็นของ package ตัวเองเป็น key เสมอ:

```go
type contextKey string
const requestIDKey contextKey = "requestID"
```

export const contextCode = `package main

import (
\t"context"
\t"fmt"
)

func fetchData(ctx context.Context, id int) (string, error) {
\tselect {
\tcase <-ctx.Done():
\t\treturn "", ctx.Err()
\tdefault:
\t\treturn fmt.Sprintf("data-%d", id), nil
\t}
}

type ctxKey string

func main() {
\t// WithCancel: normal fetch succeeds
\tctx, cancel := context.WithCancel(context.Background())
\tdefer cancel()

\tresult, err := fetchData(ctx, 1)
\tif err != nil {
\t\tfmt.Println("error:", err)
\t} else {
\t\tfmt.Println("got:", result)
\t}

\t// Cancel, then try again — now the context is done
\tcancel()
\tresult2, err2 := fetchData(ctx, 2)
\tif err2 != nil {
\t\tfmt.Println("cancelled:", err2)
\t} else {
\t\tfmt.Println("got:", result2)
\t}

\t// WithValue: attach request-scoped metadata
\tctx3 := context.WithValue(context.Background(), ctxKey("requestID"), "abc-123")
\trid := ctx3.Value(ctxKey("requestID")).(string)
\tfmt.Println("requestID:", rid)
}`;

## ข้อแลกเปลี่ยน

| สิ่งที่ได้ | ประโยชน์ | ต้นทุน |
|---------|---------|------|
| context.WithCancel | propagate cancellation tree | ต้อง call cancel() เสมอ ไม่งั้น goroutine leak |
| context.WithTimeout | deadline อัตโนมัติ | ต้อง handle context.DeadlineExceeded |
| context.WithValue | pass value ผ่าน call stack | type unsafe, ใช้ unexported key เพื่อหลีกเลี่ยง collision |
| ctx.Done() channel | non-blocking check via select | ต้อง check ในทุก loop iteration ที่อาจรันนาน |

## ความเข้าใจผิดที่พบบ่อย

- **context.WithValue เหมาะสำหรับ pass business data** — ใช้สำหรับ request-scoped metadata เท่านั้น (trace ID, auth token)
- **cancel() ทำให้ goroutine หยุดทันที** — cancel() ส่ง signal ผ่าน channel — goroutine ต้องตรวจสอบ ctx.Done() เอง
- **context ส่ง value ได้ทุก type** — context.Value() คืน any ต้องใช้ type assertion และอาจ nil

<Callout title="defer cancel() เสมอเพื่อหลีกเลี่ยง context leak">
ทุกการเรียก `context.WithCancel`, `context.WithTimeout`, หรือ `context.WithDeadline` ต้องมีการเรียก `cancel` function คู่กัน ถ้าลืมเรียก child จะยังค้างขึ้นทะเบียนอยู่กับ parent จนกว่า parent เองจะจบ — เป็น memory leak และ `go vet` (analyzer `lostcancel`) จับกรณีที่ชัดเจนที่สุดได้ตั้งแต่ compile time เรียก `cancel()` แม้ timeout จะยิงเองอยู่แล้วก็ตาม เพราะมันปล่อย timer ข้างในทันทีแทนที่จะรอให้หมดเวลาเอง Pattern idiomatic เสมอ: `ctx, cancel := context.WithTimeout(parent, d); defer cancel()`
</Callout>
