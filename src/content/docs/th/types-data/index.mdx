## ภาพรวม Type ใน Go

ทุกค่าใน Go มี type แบบ static ที่กำหนดตั้งแต่ compile time ซึ่ง Go แบ่ง type ออกเป็นสองกลุ่มหลัก:

**Value types** — ตัวแปรเก็บข้อมูลโดยตรง การ assign ค่าจะ copy ข้อมูลทั้งหมด ได้แก่ boolean, ตัวเลข (`int`, `int64`, `float64`, `uint8`, …), และ `string` รวมถึง composite value types อย่าง **array** และ **struct**

**Reference-like types** — ตัวแปรเก็บ handle ขนาดเล็กที่ชี้ไปยังข้อมูลจริงซึ่งถูก allocate ไว้ที่อื่น การ assign จะ copy ตัว handle เอง ไม่ใช่ข้อมูลข้างใน — ส่วนนี้เป็น copy ที่ถูกต้อง เหมือน copy ค่าอื่น ๆ ทั่วไป **slice** (header แบบ pointer + len + cap), **map** และ **channel** (pointer เดียว), **function**, และ **pointer** (1 word) ล้วนทำงานแบบนี้ และเพราะ handle ทั้งสอง copy ยังชี้ไปข้อมูลชุดเดียวกัน การ mutation ผ่าน handle หนึ่งจะมองเห็นได้ผ่านอีก handle ด้วย **string** ก็สร้างด้วยวิธีเดียวกันภายใน — header แบบ pointer + len — แต่พฤติกรรมจากภายนอกเหมือน value type: ข้อมูลใน string เป็น immutable จึงไม่มีทางเกิด shared-mutation ที่น่าแปลกใจแบบ slice กับ map

## โปรแกรม composite type แรกของคุณ

โปรแกรมด้านล่างนิยาม struct ชื่อ `Point` สร้าง slice `[]Point` แล้วค้นหาชื่อจาก `map[string]int` ซึ่งแสดงให้เห็น value type (`Point` ถูก copy), slice literal, และการเข้าถึง map พร้อม zero-value เมื่อ key ไม่มีอยู่

export const indexCode = `package main

import "fmt"

type Point struct {
\tX, Y int
}

func main() {
\t// Struct literal with named fields
\tp := Point{X: 3, Y: 4}
\tfmt.Println(p.X, p.Y)

\t// Slice of structs
\tpoints := []Point{
\t\t{X: 0, Y: 0},
\t\t{X: 1, Y: 2},
\t\t{X: 3, Y: 4},
\t}
\tfor _, pt := range points {
\t\tfmt.Printf("(%d, %d)\\n", pt.X, pt.Y)
\t}

\t// Map: string -> int
\tscore := map[string]int{
\t\t"Alice": 95,
\t\t"Bob":   87,
\t}
\tfmt.Println(score["Alice"])
\tfmt.Println(score["Charlie"]) // missing key -> zero value (0)
}`;

## ข้อแลกเปลี่ยน

| สิ่งที่ได้ | ประโยชน์ | ต้นทุน |
|------|---------|------|
| value type (struct, array) | predictable behavior, ไม่มี aliasing | copy cost สำหรับ type ขนาดใหญ่ |
| reference-like type (slice, map) | แชร์ data โดยไม่ต้อง copy | shared mutation — goroutine หนึ่งแก้ไขอาจกระทบอีกตัว |
| composite literals | readable initialization | syntax แตกต่างกันตาม type |

## ความเข้าใจผิดที่พบบ่อย

- **array และ slice คือสิ่งเดียวกัน** — array มีขนาดคงที่เป็นส่วนของ type เช่น `[3]int` ≠ `[4]int`; slice เป็น dynamic view ของ array
- **map safe สำหรับ concurrent access** — Go map ไม่ใช่ — ต้องใช้ `sync.Mutex` หรือ `sync.RWMutex` ถ้า goroutine หลายตัวอ่าน/เขียนพร้อมกัน

<Callout title="Value types ถูก copy; reference-like types แชร์ข้อมูล">
เมื่อคุณ assign struct ไปยังตัวแปรใหม่ — `p2 := p1` — คุณจะได้ copy ที่เป็นอิสระ การแก้ไข `p2` ไม่ส่งผลต่อ `p1` แต่ slice และ map ทำงานต่างออกไป: การ assign จะ copy แค่ header ทำให้ตัวแปรสองตัวชี้ไปข้อมูลชุดเดียวกัน ความแตกต่างนี้คือหัวใจของการตัดสินใจออกแบบส่วนใหญ่ที่คุณจะพบในโมดูลนี้
</Callout>
