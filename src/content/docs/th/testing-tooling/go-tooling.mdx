## คำสั่ง go คือมีดพับสวิส

binary `go` รวมทุกเครื่องมือที่นักพัฒนา Go ต้องการไว้ใน executable เดียว ไม่มี build system แยกต่างหาก ไม่ต้องใช้ `Makefile` สำหรับ workflow พื้นฐาน และไม่มี plugin ecosystem ที่ต้องตั้งค่า คำสั่งต่อไปนี้ครอบคลุม 90% ของการพัฒนา Go ประจำวัน

## go run — compile และ execute ในขั้นตอนเดียว

`go run` compile ไฟล์ที่ระบุและรัน binary ที่ได้ทันที เหมาะสำหรับ scripts และการทดสอบรวดเร็ว — ไม่มีไฟล์ output เหลือบน disk

```bash
go run main.go
go run .                   # รัน package ใน directory ปัจจุบัน
go run ./cmd/server        # รัน cmd sub-package เฉพาะ
```

## go build — สร้าง binary

`go build` compile package และเขียน binary ลง disk โดยไม่มี flag `-o` binary จะตั้งชื่อตาม module ใน directory ปัจจุบัน

```bash
go build .                         # build package ปัจจุบัน output: ./myapp
go build -o bin/server ./cmd/server  # build ไปยัง path เฉพาะ

# Cross-compile สำหรับ Linux/amd64 จาก macOS
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o bin/server ./cmd/server
```

flag `-ldflags="-s -w"` ลบ symbol table และ DWARF debug info ออก ลดขนาด binary อย่างมีนัยสำคัญ `CGO_ENABLED=0` รับประกัน binary ที่ static อย่างสมบูรณ์ — ไม่มี dynamic libc dependency

## go fmt — จัดรูปแบบ canonical

`go fmt` รัน `gofmt` กับไฟล์ `.go` ทั้งหมดใน package และเขียนผลลัพธ์กลับลง disk มีวิธีเดียวเท่านั้นในการจัดรูปแบบโค้ด Go

```bash
go fmt ./...       # จัดรูปแบบทุก package ใน module
gofmt -w -l ./     # เทียบเท่า: เขียนการเปลี่ยนแปลง, แสดงไฟล์ที่แก้ไข
```

ใน CI ตรวจสอบว่าโค้ดถูกจัดรูปแบบแล้ว:

```bash
gofmt -l . | grep -q . && echo "unformatted files found" && exit 1 || echo "all formatted"
```

## go vet — static analysis

`go vet` รัน static analysers ชุดหนึ่งที่ตรวจจับ bugs ที่ compiler ไม่ตรวจ: format verbs ของ `Printf` ที่ไม่ตรงกัน, unreachable code, การใช้ mutex ที่ผิด และอื่นๆ

```bash
go vet ./...
```

ตัวอย่าง issues ที่ `go vet` ตรวจพบ:

```go
fmt.Printf("%d", "hello")   // vet: format %d has arg "hello" of wrong type string
var mu sync.Mutex
mu2 := mu                   // vet: assignment copies lock value
```

`go vet` exit ด้วย non-zero status หากพบปัญหา ทำให้ fail CI pipeline ได้ง่าย

รุ่นหลัง ๆ เพิ่ม analyzer ที่คุณจะเจอในงานจริง: `waitgroup` (Go 1.25) จับ `wg.Add` ที่วางหลัง `go` statement, `hostport` (Go 1.25) แนะนำ `net.JoinHostPort` แทน `fmt.Sprintf("%s:%d", host, port)` ซึ่งพังกับ IPv6 และ `stdversion` (รันโดย `go test` ตั้งแต่ Go 1.27) รายงานการเรียก API ของ standard library ที่ใหม่กว่าบรรทัด `go` ของ module


## go fix — modernizer (Go 1.26+)

`go fix` ถูกสร้างใหม่ใน Go 1.26 บน analysis framework เดียวกับ `go vet` แทน fixer ในอดีตไม่กี่ตัว ตอนนี้มี **modernizer** เป็นสิบ ๆ ตัว: analyzer ที่เขียน idiom แบบเก่าใหม่ให้เป็น standard library ปัจจุบัน

```bash
go fix ./...            # apply modernizer ทุกตัวกับ module
go fix -diff ./...      # ดูตัวอย่างการเขียนใหม่โดยไม่แตะไฟล์
```

การเขียนใหม่ที่พบบ่อย: `for` loop ที่หาค่าต่ำสุดด้วยมือกลายเป็น `min(...)`; `sort.Slice` กลายเป็น `slices.Sort`; `for i := 0; i < n; i++` กลายเป็น `for i := range n`; สามบรรทัด `wg.Add(1)` / `go` / `defer wg.Done()` กลายเป็น `wg.Go(...)` (`waitgroupgo`); การ copy ตัวแปร loop แบบ `x := x` ถูกลบ Go 1.27 เพิ่ม `atomictypes`, `embedlit`, `slicesbackward` และ `unsafefuncs` ผู้เขียน library ยัง mark wrapper ด้วย `//go:fix inline` ได้ เพื่อให้ `go fix` inline การเรียกในทุกจุดใช้งาน — กลไกเดียวกับที่ standard library ใช้ย้าย caller ออกจาก helper ที่ deprecated

## อะไรอีกที่เปลี่ยนใน toolchain (Go 1.25–1.27)

- `go mod init` เขียนบรรทัด `go` ต่ำกว่า toolchain หนึ่ง minor version (`go 1.26.0` จาก Go 1.27) เพื่อให้ module ใหม่ build บนรุ่นก่อนหน้าได้ด้วย ยกขึ้นด้วย `go get go@1.27` เมื่อต้องใช้ feature ของ 1.27
- `go doc example.com/pkg@v1.2.3` (Go 1.27) แสดง doc ของ module version ที่ระบุ และ `go doc -ex` แสดงรายการ example ที่รันได้
- `go doc -http` (Go 1.25) เสิร์ฟ documentation ในเบราว์เซอร์ ไม่ต้องใช้ `pkgsite` สำหรับงานในเครื่องอีกแล้ว
- `go tool pprof -http` (Go 1.26) เปิดมาที่หน้า flame graph; `go tool trace -http=:6060` (Go 1.27) bind เฉพาะ localhost เว้นแต่ระบุ address เต็ม
- `go build -asan` (Go 1.25) รายงาน memory leak ตอนจบโปรแกรม; `go version -m -json` พิมพ์ build info เป็น JSON

## go doc — เรียกดู documentation

`go doc` แสดง documentation สำหรับ package, type, function, หรือ method ใดก็ได้ — โดยไม่ต้องออกจาก terminal

```bash
go doc fmt                    # ภาพรวม package
go doc fmt.Println            # ฟังก์ชันเฉพาะ
go doc net/http.Request       # type ใน sub-package
go doc -all net/http          # ทุก exported symbol ใน package
go doc -ex strings.Cut        # พิมพ์ example ที่รันได้ (Go 1.27)
go doc golang.org/x/text@v0.28.0  # module version ที่ระบุ (Go 1.27)
```

สำหรับมุมมองแบบ browser รัน `go doc -http` (Go 1.25+) หรือเรียกดูที่ `pkg.go.dev`

## รวมทุกอย่าง — CI pipeline ทั่วไป

```bash
go fmt ./... && \
go vet ./... && \
go test -race -coverprofile=coverage.out -covermode=atomic ./... && \
go build ./...
```

pipeline สี่คำสั่งนี้ตรวจจับ formatting drift, static bugs, data races, และ compilation errors ก่อนที่ code จะถูก merge

## ข้อแลกเปลี่ยน

| Tool | Benefit | Cost |
|------|---------|------|
| `go vet` | ตรวจหา common mistakes ก่อน runtime | ไม่ครอบคลุม semantic bug ทั้งหมด — ต้องใช้ staticcheck เพิ่ม |
| `go build -race` | ตรวจหา race condition ใน binary | binary ช้าลง 2-10x — ไม่เหมาะ production build |
| `gofmt` (ผ่าน `go fmt`) | ไม่มีถกเถียงเรื่อง formatting, consistent ทั้ง ecosystem | ไม่มี config — ต้องยอมรับ canonical style |
| `go doc` | documentation ใน terminal ไม่ต้องออก browser | ไม่มี search full-text — ต้องรู้ชื่อ package/function แล้ว |

## ความเข้าใจผิดที่พบบ่อย

- **`go fmt` เป็นแค่ style เท่านั้น** — gofmt เป็น de facto standard — PR ที่ไม่ผ่าน gofmt ถูก reject ใน project หลักทุกที่
- **`go vet` ตรวจสอบครบทุก bug** — `go vet` ตรวจ subset ของ common mistakes — ใช้ staticcheck เพิ่มสำหรับ production codebase
- **`go generate` ทำงานอัตโนมัติตอน build** — `go generate` ต้องรันเอง ไม่ได้รันตอน `go build` — ต้อง explicit ใน Makefile หรือ CI
- **GOPATH ยังจำเป็น** — Go modules (`go.mod`) แทน GOPATH อย่างสมบูรณ์ตั้งแต่ Go 1.16

> 💡 ตัวอย่างจากของจริง
>
> **Kubernetes** CI pipeline รัน `go vet` + staticcheck + race detector ทุก PR — ตรวจจับ bug ก่อน merge เป็น standard
>
> **Go standard library** enforce gofmt ใน code review — ไม่มีข้อยกเว้น
>
> **Docker** ใช้ `go tool pprof` เพื่อ profile container daemon memory usage และ optimize hot path
