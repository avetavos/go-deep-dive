## JSON ใน Go

Package `encoding/json` แปลงค่า Go เป็น JSON text (marshaling) และแปลง JSON text กลับเป็นค่า Go (unmarshaling) function หลักสองตัวคือ:

```go
data, err := json.Marshal(v)       // Go value → []byte (JSON)
err        = json.Unmarshal(data, &v) // []byte (JSON) → Go value
```

`Marshal` รับค่าใดก็ได้และคืน `[]byte` `Unmarshal` เขียนลงในค่าที่ชี้โดย argument ที่สอง — ส่ง pointer เสมอเพื่อให้ function แก้ไขตัวแปรได้

## Struct tags

**Struct tag** คือ raw-string literal บน field ของ struct ที่ให้ metadata Package `encoding/json` อ่าน tag `json:"name"` เพื่อควบคุมการ serialize:

```go
type User struct {
    Name  string `json:"name"`
    Email string `json:"email,omitempty"`
    Age   int    `json:"age"`
}
```

syntax ของ tag คือ `` `json:"<name>[,options]"` `` option ที่พบบ่อย:

| Tag | ผล |
|-----|--------|
| `json:"name"` | ใช้ `name` เป็น JSON key แทนชื่อ field |
| `json:"name,omitempty"` | ละเว้น field นี้เมื่อเป็น `false`, `0`, nil pointer/interface หรือ empty string/slice/map/array — **ไม่รวม** zero struct หรือ zero `time.Time` |
| `json:"name,omitzero"` (Go 1.24) | ละเว้น field นี้เมื่อเป็น zero value ของ type นั้น รวมถึง struct และ `time.Time` — เรียก method `IsZero() bool` ถ้า type มี method นี้ |
| `json:"-"` | ละเว้น field นี้เสมอ |

`omitempty` เช็กแค่ความ "ว่าง" ระดับภาษา (zero value ของ basic type หรือความยาวเป็น 0 สำหรับ slice/map) struct — แม้ทุก field ข้างในจะเป็น zero — ไม่ถือว่า "ว่าง" ตามกฎนี้ `omitempty` จึงไม่มีวันละเว้น struct `time.Time` เองก็เป็น struct ผลจึงเหมือนกัน: `time.Time{}` ที่เป็น zero ยัง marshal ออกมาเป็น `"0001-01-01T00:00:00Z"`

```go
type Location struct {
	City string
}

type Event struct {
	Name     string    `json:"name"`
	Location Location  `json:"location,omitempty"` // struct — NOT omitted when zero
	When     time.Time `json:"when,omitempty"`     // time.Time — NOT omitted when zero
}

e := Event{Name: "party"} // Location and When left at their zero values
data, _ := json.Marshal(e)
fmt.Println(string(data))
// {"name":"party","location":{"City":""},"when":"0001-01-01T00:00:00Z"}
```

`omitzero` (Go 1.24) แก้ปัญหานี้ตรงๆ: มันละเว้น field ทุกครั้งที่ค่าเท่ากับ zero value ของ type นั้น รวมถึง struct ด้วย และเรียก `IsZero()` บน field เมื่อ type นั้นนิยาม method ไว้ — ซึ่งเป็นเหตุผลที่มันถือว่า `time.Time{}` เป็นค่าว่างได้ถูกต้อง

```go
type Event2 struct {
	Name     string    `json:"name"`
	Location Location  `json:"location,omitzero"` // omits zero structs too
	When     time.Time `json:"when,omitzero"`     // uses time.Time.IsZero()
}

e2 := Event2{Name: "party"}
data2, _ := json.Marshal(e2)
fmt.Println(string(data2))
// {"name":"party"}
```

## Nested structs

Field ของ struct สามารถเป็น struct ได้เช่นกัน `json.Marshal` จะ recurse เข้าไปโดยอัตโนมัติ:

```go
type Address struct {
    City    string `json:"city"`
    Country string `json:"country"`
}

type User struct {
    Name    string  `json:"name"`
    Age     int     `json:"age"`
    Address Address `json:"address"`
}
```

JSON ที่ได้จะฝัง address object ไว้ภายใต้ key `"address"`

## map[string]any — การ unmarshal แบบยืดหยุ่น

เมื่อยังไม่มี struct type ล่วงหน้า ให้ unmarshal ลงใน `map[string]any` แต่ละค่า JSON จะกลายเป็น Go counterpart ที่เป็นธรรมชาติ: `string`, `float64`, `bool`, `[]any`, `map[string]any` หรือ `nil`

```go
var m map[string]any
json.Unmarshal([]byte(`{"lang":"Go","version":1.22}`), &m)
fmt.Println(m["lang"])    // Go
fmt.Println(m["version"]) // 1.22  (float64)
```

export const encodingJsonCode = `package main

import (
\t"encoding/json"
\t"fmt"
)

type Address struct {
\tCity    string \`json:"city"\`
\tCountry string \`json:"country"\`
}

type User struct {
\tName    string  \`json:"name"\`
\tAge     int     \`json:"age"\`
\tEmail   string  \`json:"email,omitempty"\`
\tAddress Address \`json:"address"\`
}

func main() {
\t// Marshal a struct — Email is set, so it appears
\tu := User{
\t\tName:  "Alice",
\t\tAge:   30,
\t\tEmail: "alice@example.com",
\t\tAddress: Address{
\t\t\tCity:    "Bangkok",
\t\t\tCountry: "Thailand",
\t\t},
\t}
\tdata, err := json.Marshal(u)
\tif err != nil {
\t\tfmt.Println("marshal error:", err)
\t\treturn
\t}
\tfmt.Println(string(data))

\t// omitempty: Email is empty, so it is omitted
\tu2 := User{Name: "Bob", Age: 25, Address: Address{City: "London", Country: "UK"}}
\tdata2, _ := json.Marshal(u2)
\tfmt.Println(string(data2))

\t// Unmarshal back into a struct
\tvar result User
\terr = json.Unmarshal(data, &result)
\tif err != nil {
\t\tfmt.Println("unmarshal error:", err)
\t\treturn
\t}
\tfmt.Printf("Name: %s, City: %s\\n", result.Name, result.Address.City)

\t// map[string]any — flexible unmarshaling
\traw := \`{"lang":"Go","version":1.22,"stable":true}\`
\tvar m map[string]any
\t_ = json.Unmarshal([]byte(raw), &m)
\tfmt.Println(m["lang"], m["version"], m["stable"])
}`;

## Unexported field มองไม่เห็นเลย ไม่ใช่แค่ถูกละเว้น

field ที่ unexported (ขึ้นต้นด้วยตัวพิมพ์เล็ก) ไม่ได้แค่ถูกข้ามด้วย semantics ของ `omitempty` — `encoding/json` มองไม่เห็นมันเลยไม่ว่าจะผ่าน reflection หรือทางไหนก็ตาม ใส่ tag ยังไงก็ไม่ช่วย:

```go
type Account struct {
    Name   string `json:"name"`
    secret string // never marshaled, never populated by Unmarshal, no matter what
}
```

`json.Marshal(Account{Name: "root", secret: "swordfish"})` จะได้ `{"name":"root"}` — field `secret` ไม่มีตัวตนเลยเท่าที่ package นี้เกี่ยวข้อง นี่คือสาเหตุที่พบบ่อยของความสับสน "ทำไม field ของฉันไม่ขึ้น" เมื่อโค้ดที่ AI เขียน copy ชื่อ field ตัวพิมพ์เล็กมาจากที่อื่นในโค้ดเบส

## decode เป็น any: float64 เสียความละเอียด และ json.Number

เมื่อไม่มี struct type เป้าหมาย `Unmarshal`/`Decode` จะแปลงตัวเลข JSON ทุกตัวเป็น `float64` ของ Go — รวมถึงจำนวนเต็มด้วย `float64` มี mantissa แค่ 53 bit ดังนั้นจำนวนเต็มที่มากกว่า 2^53 (9007199254740992) จะเสียความละเอียดเงียบๆ ทันทีที่กลายเป็น `any`:

```go
var v any
json.Unmarshal([]byte(`{"n": 9007199254740993}`), &v)
// v["n"] is 9.007199254740992e+15 — the trailing 3 became a 2
```

`json.Decoder.UseNumber()` แก้ปัญหานี้: มัน decode ตัวเลข JSON เป็น `json.Number` ซึ่งเป็น string type ที่เก็บ text ต้นฉบับไว้ แล้วค่อยแปลงเป็นตัวเลขเองด้วย `.Int64()` หรือ `.Float64()` เมื่อต้องการ numeric type จริงๆ — field ID ที่เป็นเลขใหญ่คือกรณีคลาสสิกที่วิธีนี้ช่วยได้

## Decoder เทียบกับ Unmarshal: DisallowUnknownFields และ streaming ด้วย More()

`json.Unmarshal(data, &v)` ต้องการ payload ทั้งหมดในหน่วยความจำเป็น `[]byte` `json.NewDecoder(r).Decode(&v)` อ่านตรงจาก `io.Reader` — ไม่ต้องมี buffer เต็มก่อน และรองรับสองอย่างที่ `Unmarshal` ไม่มี:

- **`dec.DisallowUnknownFields()`** ปฏิเสธ JSON key ใดๆ ที่ไม่มี field ของ struct ตรงกัน แทนที่จะเพิกเฉยเงียบๆ มีประโยชน์ที่ขอบของ API ที่ field พิมพ์ผิดหรือไม่คาดคิดควรเป็น error ที่ชัดเจน
- **`dec.More()`** ให้ decode stream ของค่าทีละตัว — เช่น element ของ JSON array — โดยไม่ต้องเก็บ array ทั้งหมดไว้ในหน่วยความจำ

```go
dec := json.NewDecoder(r)
dec.Token() // consume the opening '['
for dec.More() {
    var item Item
    dec.Decode(&item) // one element at a time
}
```

## []byte, time.Time และ nil slice เทียบกับ slice ว่าง

กฎการ encode สามข้อที่พลาดได้ง่ายเมื่อเขียน API contract เอง:

- **`[]byte`** marshal เป็น JSON string แบบ base64 (RFC 4648) ไม่ใช่ JSON array ของตัวเลข
- **`time.Time`** marshal เป็น string แบบ RFC 3339 โดย default (รูปแบบเวลาในตัวรูปแบบเดียวของ `json.Marshal`)
- **slice ที่เป็น `nil` marshal เป็น `null`; slice ว่างที่ไม่ใช่ nil (`[]T{}`) marshal เป็น `[]`** endpoint `GET /items` ที่ลืม initialize slice ผลลัพธ์จะส่ง `"items":null` ให้ client ที่คาดหวัง `"items":[]` — เป็น bug ที่กระทบ API-compatibility จริงๆ ไม่ใช่แค่เรื่องความสวยงาม

## Custom MarshalJSON และ alias trick

type สามารถควบคุมการ encode JSON ของตัวเองได้โดย implement `MarshalJSON() ([]byte, error)` กับดักคือ: การเรียก `json.Marshal` บน receiver *ข้างใน* method นั้นจะเรียก `MarshalJSON` ซ้ำอีกครั้ง วนซ้ำไม่รู้จบ วิธีแก้คือ **alias trick** — นิยาม type ใหม่ที่มี field เดิมทุกตัวแต่ไม่มี method ของ type เดิมเลย แล้ว marshal type ใหม่นั้นแทน:

```go
type Node struct {
    Value    int    `json:"value"`
    Children []Node `json:"children"`
}

func (n Node) MarshalJSON() ([]byte, error) {
    type alias Node // same fields, no methods — breaks the recursive call
    return json.Marshal(struct {
        Total int `json:"total"`
        alias
    }{
        Total: n.Value + len(n.Children),
        alias: alias(n),
    })
}
```

`type alias Node` สร้าง named type ใหม่ที่มี field layout ตรงกับ `Node` เป๊ะ แต่มี method set ว่างเปล่าใหม่ ดังนั้น `json.Marshal(alias(n))` จึงไปใช้ default struct encoder แทนที่จะเรียก `MarshalJSON` ซ้ำอีกครั้ง

export const encodingJsonAdvancedCode = `package main

import (
\t"bytes"
\t"encoding/json"
\t"fmt"
\t"strings"
\t"time"
)

// secret is unexported — encoding/json can never see it, tag or no tag
type Account struct {
\tName   string \`json:"name"\`
\tsecret string
}

// Node uses a MarshalJSON with the "alias trick" to avoid infinite recursion:
// aliasing Node to a new type with the same fields drops the MarshalJSON method,
// so encoding it with the alias type calls the default struct encoder, not itself.
type Node struct {
\tValue    int    \`json:"value"\`
\tChildren []Node \`json:"children"\`
}

func (n Node) MarshalJSON() ([]byte, error) {
\ttype alias Node // same fields, no methods — breaks the recursive call
\treturn json.Marshal(struct {
\t\tTotal int \`json:"total"\`
\t\talias
\t}{
\t\tTotal: n.Value + len(n.Children),
\t\talias: alias(n),
\t})
}

type Blob struct {
\tRaw   []byte    \`json:"raw"\`
\tWhen  time.Time \`json:"when"\`
\tTags  []string  \`json:"tags"\`
\tEmpty []string  \`json:"empty"\`
}

func main() {
\t// 1. unexported field is invisible to encoding/json
\ta := Account{Name: "root", secret: "swordfish"}
\tdata, _ := json.Marshal(a)
\tfmt.Println("unexported dropped:", string(data))

\t// 2. decoding into any: numbers become float64, large ints lose precision
\tvar any1 any
\tjson.Unmarshal([]byte(\`{"n": 9007199254740993}\`), &any1)
\tm := any1.(map[string]any)
\tfmt.Printf("as any: %v (%T)\\n", m["n"], m["n"])

\t// json.Number keeps the exact text instead
\tdec := json.NewDecoder(strings.NewReader(\`{"n": 9007199254740993}\`))
\tdec.UseNumber()
\tvar any2 any
\tdec.Decode(&any2)
\tm2 := any2.(map[string]any)
\tnum := m2["n"].(json.Number)
\tfmt.Printf("as json.Number: %v (%T) -> Int64: %v\\n", num, num, func() string {
\t\ti, err := num.Int64()
\t\treturn fmt.Sprintf("%d err=%v", i, err)
\t}())

\t// 3. DisallowUnknownFields rejects fields the struct doesn't declare
\ttype Strict struct {
\t\tName string \`json:"name"\`
\t}
\tvar s Strict
\tdec2 := json.NewDecoder(strings.NewReader(\`{"name":"Ada","extra":1}\`))
\tdec2.DisallowUnknownFields()
\terr := dec2.Decode(&s)
\tfmt.Println("DisallowUnknownFields error:", err)

\t// 4. Decoder streaming with dec.More() over a JSON array, one element at a time
\tdec3 := json.NewDecoder(strings.NewReader(\`[1,2,3]\`))
\tdec3.Token() // consume the opening '['
\tvar nums []int
\tfor dec3.More() {
\t\tvar n int
\t\tdec3.Decode(&n)
\t\tnums = append(nums, n)
\t}
\tfmt.Println("streamed with dec.More():", nums)

\t// 5. []byte marshals as base64, time.Time as RFC3339
\tb := Blob{
\t\tRaw:   []byte("hi"),
\t\tWhen:  time.Date(2026, 9, 13, 12, 0, 0, 0, time.UTC),
\t\tTags:  []string{"a"},
\t\tEmpty: []string{},
\t}
\tvar nilTags []string
\tb.Tags = nilTags // nil slice
\tdata2, _ := json.Marshal(b)
\tfmt.Println("[]byte + time.Time:", string(data2))

\t// 6. custom MarshalJSON with the alias trick against infinite recursion
\ttree := Node{Value: 1, Children: []Node{{Value: 2}, {Value: 3}}}
\tdata3, _ := json.Marshal(tree)
\tfmt.Println("custom MarshalJSON:", string(data3))

\t// 7. nil slice encodes as null, empty slice encodes as []
\ttype Lists struct {
\t\tNil   []int \`json:"nil"\`
\t\tEmpty []int \`json:"empty"\`
\t}
\tvar buf bytes.Buffer
\tjson.NewEncoder(&buf).Encode(Lists{Nil: nil, Empty: []int{}})
\tfmt.Print("nil vs empty slice: ", buf.String())
}`;

## encoding/json/v2 (Go 1.27)

Go 1.27 มาพร้อม `encoding/json/v2` และ package ระดับล่างคู่กัน `encoding/json/jsontext` ในสถานะ stable ทุกอย่างข้างบนยังใช้ได้: API ของ v1 `encoding/json` ไม่เปลี่ยน แต่ตอนนี้ *สร้างอยู่บน v2* โปรแกรมเดิมจึงได้ decoder ที่เร็วขึ้นฟรี ๆ (ปิดได้ด้วย `GOEXPERIMENT=nojsonv2` ถ้าเจอพฤติกรรมต่างกัน)

ให้ import v2 เมื่อต้องการ API และ default ที่เข้มงวดกว่า:

export const jsonV2Code = `package main

import (
\t"encoding/json/v2"
\t"fmt"
\t"os"
)

type User struct {
\tName  string \`json:"name"\`
\tEmail string \`json:"email,omitempty"\`
\tAge   int    \`json:"age"\`
}

func main() {
\tu := User{Name: "Ada", Age: 36}

\tdata, err := json.Marshal(u) // same shape as v1 …
\tfmt.Println(string(data), err)

\tvar back User
\terr = json.Unmarshal(data, &back)
\tfmt.Printf("%+v %v\\n", back, err)

\tdata, _ = json.Marshal(map[string]int{"b": 2, "a": 1}, json.Deterministic(true)) // … plus variadic Options
\tfmt.Println(string(data))

\t_ = json.MarshalWrite(os.Stdout, u) // straight to an io.Writer
\tfmt.Println()

\t// stricter defaults: duplicate keys are rejected
\terr = json.Unmarshal([]byte(\`{"name":"A","name":"B"}\`), &back)
\tfmt.Println("duplicate key:", err)
}`;

`json.UnmarshalRead(r, &u)` คือด้านกลับของ `MarshalWrite` — decode จาก `io.Reader` อย่าง `resp.Body` ได้ตรง ๆ

สิ่งที่ต่างจาก v1:

| เรื่อง | v1 `encoding/json` | v2 `encoding/json/v2` |
|------|--------------------|-----------------------|
| UTF-8 ผิดรูปใน string | แทนที่เงียบ ๆ | **ปฏิเสธ** |
| key ซ้ำใน object | ตัวหลังชนะ | **ปฏิเสธ** |
| การจับคู่ชื่อ field | ไม่สนตัวพิมพ์ | ต้องตรงเป๊ะโดย default (`json.MatchCaseInsensitiveNames(true)` เพื่อผ่อน) |
| Options | setter ระดับ `Encoder` | ค่า `Options` ต่อการเรียก ประกอบกันได้ |
| ฝัง field ของ struct | anonymous field | tag `json:",embed"` (ชื่อเก่า `inline` ถูกเปลี่ยน) |
| ความเร็ว Unmarshal | baseline | เร็วขึ้นอย่างมีนัยสำคัญ Marshal เท่าเดิม |

การจับคู่ชื่อ field แบบเข้มงวดของ v2 พลาดได้ง่ายแบบเงียบ ๆ เมื่อ import `encoding/json/v2` แล้ว unmarshal key ตัวพิมพ์เล็กลง field ที่ไม่มี tag จะคืน error เป็น `nil` และปล่อย field ว่างไว้:

```go
type User struct {
	Name string // no tag
}

var u User
err := json.Unmarshal([]byte(`{"name":"Ada"}`), &u)
// v1: err == nil, u.Name == "Ada" — matched case-insensitively
// v2: err == nil, u.Name == ""    — no exact match, field left alone
```

v1 จับคู่ `name` กับ `Name` แบบไม่สนตัวพิมพ์ แต่ v2 ต้องตรงตัวพิมพ์ (หรือมี tag `json:"name"`) เป็นค่าเริ่มต้น ดังนั้นเวลาย้าย code มาใช้ v2 ให้ใส่ tag ให้ชัดเจนเสมอ

`jsontext` คือชั้น streaming ที่อยู่ข้างใต้: `jsontext.Decoder` และ `jsontext.Encoder` เดินผ่าน document เป็น `Token` และ `Value` พร้อมตรวจ syntax ไปด้วย เหมาะกับ payload ขนาดใหญ่มากหรือการเขียน JSON ใหม่โดยไม่ decode เป็นค่า Go

```go
dec := jsontext.NewDecoder(r)
for {
    tok, err := dec.ReadToken()
    if err == io.EOF { break }
    // inspect tok.Kind(): '{', '}', '"', '0', …
}
```

หลักคิดสำหรับปี 2026: โค้ดเดิมและ wire format ที่ยอมรับ input หลวม ๆ ใช้ v1 ต่อไป service ใหม่เริ่มที่ v2 เพื่อให้ JSON ผิดรูป fail เสียงดังตั้งแต่ขอบระบบ

## ข้อแลกเปลี่ยน

| สิ่งที่ได้ | ประโยชน์ | ต้นทุน |
|---------|---------|------|
| json.Marshal/Unmarshal | ง่าย, ไม่ต้อง schema | reflect-based — ช้ากว่า code-gen 2-5x |
| struct tags (json:"name") | control field names, omitempty | runtime-only — ไม่มี compile-time check ว่า tag ถูกต้อง |
| json.Decoder (streaming) | decode large/stream JSON โดยไม่ load ทั้งหมดใน memory | API ซับซ้อนกว่า Unmarshal |
| omitempty | ไม่ส่ง zero value ใน JSON | 0, false, "" ถือเป็น empty — อาจ surprise |

## ความเข้าใจผิดที่พบบ่อย

- **json.Marshal/Unmarshal thread-safe** — ใช่ — แต่ json.Decoder/Encoder แต่ละ instance ไม่ thread-safe อย่าแชร์ข้าม goroutine
- **unexported field ถูก marshal** — ไม่ — unexported field ถูก ignore โดย encoding/json ไม่ว่าจะมี tag หรือไม่
- **omitempty ทำงานกับ pointer เหมือน value** — omitempty บน *T: nil → omit, non-nil → include แม้ว่า value ข้างใน pointer เป็น zero
- **field ที่เป็น any ใน struct marshal เป็น null เสมอ** — marshal ตาม concrete type ที่ store อยู่ใน interface ตอน runtime

> 💡 ตัวอย่างจากของจริง
>
> **Kubernetes API**: ทุก Kubernetes resource (Pod, Deployment, Service) marshal/unmarshal ผ่าน encoding/json — struct tags ควบคุม JSON key ทั้งหมด
>
> **Go REST API**: json.NewDecoder(r.Body).Decode(&req) คือ pattern มาตรฐานที่ทุก Go API server ใช้สำหรับ parse request body

<Callout title="เฉพาะ exported field เท่านั้นที่ถูก marshal; tag ควบคุมชื่อ JSON key">
Field ที่ขึ้นต้นด้วยตัวอักษรพิมพ์เล็กเป็น unexported และ `encoding/json` จะมองไม่เห็นเลย — จะไม่ปรากฏใน output และจะไม่ถูก populate ระหว่าง unmarshal ไม่ว่าจะเขียน tag อะไรก็ตาม ควรทำให้ field ที่ต้องการ serialize ขึ้นต้นด้วยตัวพิมพ์ใหญ่เสมอ จากนั้น tag `json:"name"` จะควบคุมชื่อ key ใน JSON output โดยอิสระจากชื่อ field ใน Go ทำให้สามารถใช้ naming convention ของ Go (`UserID`) และได้ JSON ที่สะอาด (`"user_id"`) ในเวลาเดียวกัน
</Callout>

## อ่านโค้ดที่ AI เขียน

โค้ด `encoding/json` ที่ AI เขียนมักดูครบถ้วนแต่แอบสมมติ schema ที่ไม่เคยตรวจสอบจริง เช็กสิ่งเหล่านี้ก่อนเชื่อ:

- field ที่ต้องปรากฏใน JSON ขึ้นต้นด้วยตัวพิมพ์ใหญ่หรือไม่? field ตัวพิมพ์เล็กจะไม่ serialize เลยเงียบๆ โดยไม่มี error จาก `Marshal` หรือ `Unmarshal`
- มีการ type-assert ค่า `any` ที่ decode มาตรงๆ เป็น `int`, `int64` หรือ numeric type อื่นหรือไม่? ตัวเลข JSON ทุกตัว decode เป็น `float64` เว้นแต่ target เป็น struct field ที่เจาะจงหรือตั้ง `UseNumber()` ไว้
- tag `omitempty` อยู่บน field ที่เป็น `struct` หรือ `time.Time` แล้วสมมติว่ามันจะถูกละเว้นเมื่อเป็น zero หรือไม่? มันจะไม่ถูกละเว้น — มีแค่ `omitzero` (Go 1.24) เท่านั้นที่ทำแบบนั้น
- field ผลลัพธ์ที่เป็น `[]T` ถูกปล่อยเป็น nil เมื่อผลลัพธ์ว่างหรือไม่ ในขณะที่ผู้ใช้ API คาดหวัง `[]` ไม่ใช่ `null`?
- `MarshalJSON` แบบ custom เรียก `json.Marshal` บน `n` (receiver) ตรงๆ แทนที่จะเป็น alias type หรือไม่ — นี่คือ infinite recursion ที่จะโผล่ตอน runtime เท่านั้น?
- โค้ดที่ต้องปฏิเสธ field ที่ไม่คาดคิดใช้ `Unmarshal` ธรรมดาแทนที่จะใช้ `Decoder` พร้อม `DisallowUnknownFields()` หรือไม่?

<SpotTheBug code={`func parseCount(body []byte) (int, error) {
	var v map[string]any
	if err := json.Unmarshal(body, &v); err != nil {
		return 0, err
	}
	count := v["count"].(int) // ???
	return count, nil
}`}>

`json.Unmarshal` ลงใน `map[string]any` จะแปลงตัวเลข JSON ทุกตัวเป็น `float64` ไม่เคยเป็น `int` — ดังนั้น `v["count"].(int)` จะ panic กับ input ที่ถูกต้องทุกตัว:

```text
recovered: interface conversion: interface {} is float64, not int
```

แก้ได้ด้วย type assertion ที่ถูกต้องพร้อมแปลง type อย่างชัดเจน หรือหลีกเลี่ยง map ทั้งหมดโดย decode ลงใน struct ที่มี field `Count int` ที่กำหนด type ไว้ ให้ `encoding/json` แปลงตัวเลขให้เอง:

```go
count, ok := v["count"].(float64)
if !ok {
    return 0, fmt.Errorf("count: not a number")
}
return int(count), nil
```

</SpotTheBug>
