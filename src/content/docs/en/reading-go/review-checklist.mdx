This is the checklist to run down — by eye, on any diff, yours or an AI's — after the tools in **[Verification Tools](/go/en/reading-go/verification-tools/)** have run and come back clean. It fits on one printed page on purpose: a checklist nobody actually opens during a review is worthless. Every line links to the lesson that explains *why*, so this page stays a list, not a re-run of the course.

## Errors

- Does every `error` return get checked before the value next to it is used?
- Is any `error` handled twice — logged **and** returned up the stack? See **[Error Values](/go/en/errors-generics/error-values/)**.
- Does a `:=` inside an `if`/`for` accidentally shadow an outer `err`? See **[Variables & Types](/go/en/basics/variables-types/)**.
- Is a concrete error type ever assigned to an `error`-typed variable and returned as-is? See **[A nil pointer inside an interface is not nil](/go/en/methods-interfaces/interfaces/)**.
- Does every `errors.As` call pass a pointer (`&target`), not the target itself? See **[Wrapping Errors](/go/en/errors-generics/wrapping/)**.
- Is `recover()` called directly inside the deferred function — never through a helper one call away? See **[Panic and Recover](/go/en/errors-generics/panic-recover/)**.
- Does any package outside `main` call `log.Fatal` or `os.Exit`, skipping its callers' `defer`s? See **[Panic and Recover](/go/en/errors-generics/panic-recover/)**.

## Concurrency

- Does every goroutine have a visible exit condition — a closed channel, a cancelled `ctx`, or a value it is waiting for? See **[Goroutines](/go/en/concurrency/goroutines/)**.
- Is `wg.Add` called before the goroutine starts, from the same goroutine that calls `wg.Wait`? See **[Goroutines](/go/en/concurrency/goroutines/)**.
- Does every goroutine that can panic recover from inside itself? See **[Panic and Recover](/go/en/errors-generics/panic-recover/)**.
- Is any type containing a `sync.Mutex` (or similar) ever used or passed by value? See **[The sync package](/go/en/concurrency/sync-primitives/)**.
- If a loop launches goroutines or defers closures, does the `go.mod` `go` directive actually guarantee per-iteration variables (1.22+), or is the loop var captured explicitly? See **[Functions](/go/en/basics/functions/)**.
- Does a bare `break` inside `select` inside `for` actually reach the loop it looks like it targets? See **[Control Flow](/go/en/basics/control-flow/)**.
- Does background work reuse a request-scoped `context.Context` it should have detached with `context.WithoutCancel`, or get stored in a struct field? See **[Context](/go/en/concurrency/context/)**.

## Resources

- Is every `defer` that closes/unlocks/releases something scoped to one acquisition, not accumulating across a loop? See **[io and bufio](/go/en/stdlib/io-bufio/)**.
- Is a resource used (`resp.Body`, a file, a lock) only after the error from acquiring it has been checked? See **[The client side](/go/en/stdlib/net-http/)**.
- Does every `http.Client` used outside a quick script set `Timeout`? See **[The client side](/go/en/stdlib/net-http/)**.

## API contract

- Is `resp.StatusCode` checked before the response body is trusted as data? See **[The client side](/go/en/stdlib/net-http/)**.
- Does `omitempty` sit on a `time.Time` or struct field expecting it to omit the zero value? See **[encoding/json](/go/en/stdlib/encoding-json/)**.
- Does every field the JSON contract needs actually get exported (and tagged)? See **[encoding/json](/go/en/stdlib/encoding-json/)**.
- Is a nil slice returned where the contract requires `[]`, or vice versa? See **[encoding/json](/go/en/stdlib/encoding-json/)**.

## Types

- Does an `append` on a sub-slice risk overwriting a parent slice's backing array? See **[Slices](/go/en/types-data/slices/)**.
- Is a map ever written to before it has been initialized with `make` or a literal? See **[Maps](/go/en/types-data/maps/)**.
- Does any call site still assume `maps.Keys`/`maps.Values` return a slice instead of an `iter.Seq`? See **[Iterators](/go/en/errors-generics/iterators/)**.

## Tooling & style

- Is every `time.Sleep`/duration literal explicit about its unit (`5 * time.Second`, never a bare `5`)? See **[time](/go/en/stdlib/time/)**.
- Does a new interface have more than one real implementation — or is `any`/a concrete type simpler? Is `interface{}` used where `any` reads better? Is a receiver named after the type, not `this`/`self`? See **[Interfaces](/go/en/methods-interfaces/interfaces/)** and **[Methods](/go/en/methods-interfaces/methods/)**.
