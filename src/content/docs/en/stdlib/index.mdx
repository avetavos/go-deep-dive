## Go's batteries-included standard library

One of Go's defining characteristics is that the language ships with a comprehensive standard library — no `npm install`, no `pip install`, no Maven coordinates required for the vast majority of everyday tasks. The library covers HTTP servers and clients, JSON encoding, cryptography, file I/O, text processing, concurrency primitives, and much more. This philosophy keeps dependency trees shallow, binaries self-contained, and upgrade risks low.

The table below shows what this module covers and which package delivers it.

| Topic | Package(s) | Lesson |
|---|---|---|
| Formatted I/O, text, numbers | `fmt`, `strings`, `strconv` | fmt & strings |
| Dates, durations, timers | `time` | time |
| JSON marshaling / unmarshaling | `encoding/json` | encoding/json |
| Streaming I/O, scanning | `io`, `bufio` | io & bufio |

## Why standard library first?

Real Go programs reach for `fmt.Println`, `strings.Split`, `time.Now`, and `json.Marshal` within the first few lines. Understanding these packages deeply means you will recognise idiomatic Go in any codebase you encounter, and you will reach for the right tool instead of pulling in an extra dependency.

## Trade-offs

| What you get | Benefit | Cost |
|---------|---------|------|
| Batteries-included standard library | No external package install for basic tasks | Opinionated API — less flexible than third-party alternatives |
| `encoding/json` (reflection-based) | No code generation step | Slower than a code-gen approach such as easyjson |
| `fmt` uses reflection | Print any value | Slower than a structured logger in production |
| `net/http` built in | Deploy an HTTP server with zero dependencies | `net/http` gained method + wildcard routing in 1.22 (`GET /items/{id}`) — third-party routers now mostly add value through their middleware ecosystem |

## Common Misconceptions

- **The standard library fits every use case** — some jobs still need a third party: `log/slog` has been in the standard library since 1.21, but zap/zerolog (alternative structured logging), chi/gin (advanced routing), and gorm (an ORM) remain third-party.
- **fmt.Println is too slow for production** — fmt only becomes a problem when logging is on a hot path; benchmark before you optimize.
- **encoding/json is the only option for JSON in Go** — jsoniter, easyjson, and sonic are 2-5x faster for high-throughput use cases.

> 💡 Real-world example
>
> **Kubernetes** relies mainly on the standard library — `net/http` for the API server, `encoding/json` for resource serialization, `time` for leases and timeouts.
>
> **Docker** ships as a single binary with no runtime to install — possible because Go compiles a static binary with the standard library baked in.
>
> **Prometheus** uses `net/http` for its `/metrics` endpoint and `time` for the scrape interval — no external HTTP framework needed.
