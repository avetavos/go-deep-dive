## JSON in Go

The `encoding/json` package converts Go values to JSON text (marshaling) and JSON text back to Go values (unmarshaling). The two central functions are:

```go
data, err := json.Marshal(v)       // Go value → []byte (JSON)
err        = json.Unmarshal(data, &v) // []byte (JSON) → Go value
```

`Marshal` takes any value and returns a `[]byte`. `Unmarshal` writes into the value pointed to by the second argument — always pass a pointer so the function can modify the variable.

## Struct tags

A **struct tag** is a raw-string literal on a struct field that provides metadata. The `encoding/json` package reads `json:"name"` tags to control serialization:

```go
type User struct {
    Name  string `json:"name"`
    Email string `json:"email,omitempty"`
    Age   int    `json:"age"`
}
```

The tag syntax is `` `json:"<name>[,options]"` ``. Common options:

| Tag | Effect |
|-----|--------|
| `json:"name"` | Use `name` as the JSON key instead of the field name |
| `json:"name,omitempty"` | Omit this field when it is `false`, `0`, a nil pointer/interface, or an empty string/slice/map/array — **not** a zero struct or a zero `time.Time` |
| `json:"name,omitzero"` (Go 1.24) | Omit this field when it is the zero value of its type, including structs and `time.Time` — honours an `IsZero() bool` method if the type has one |
| `json:"-"` | Always omit this field |

`omitempty` only checks for "emptiness" at the language level (the field's zero value for basic types, or length zero for slices/maps). A struct value — even one whose fields are all zero — is never "empty" by that rule, so `omitempty` never omits it. `time.Time` is a struct, so the same applies: a zero `time.Time{}` is still marshaled, as `"0001-01-01T00:00:00Z"`.

```go
type Location struct {
	City string
}

type Event struct {
	Name     string    `json:"name"`
	Location Location  `json:"location,omitempty"` // struct — NOT omitted when zero
	When     time.Time `json:"when,omitempty"`     // time.Time — NOT omitted when zero
}

e := Event{Name: "party"} // Location and When left at their zero values
data, _ := json.Marshal(e)
fmt.Println(string(data))
// {"name":"party","location":{"City":""},"when":"0001-01-01T00:00:00Z"}
```

`omitzero` (Go 1.24) fixes exactly this: it omits a field whenever the field's value equals its type's zero value, structs included, and it calls `IsZero()` on the field when the type defines one — which is how it correctly treats `time.Time{}` as empty.

```go
type Event2 struct {
	Name     string    `json:"name"`
	Location Location  `json:"location,omitzero"` // omits zero structs too
	When     time.Time `json:"when,omitzero"`     // uses time.Time.IsZero()
}

e2 := Event2{Name: "party"}
data2, _ := json.Marshal(e2)
fmt.Println(string(data2))
// {"name":"party"}
```

## Nested structs

Struct fields can themselves be structs. `json.Marshal` recurses into them automatically:

```go
type Address struct {
    City    string `json:"city"`
    Country string `json:"country"`
}

type User struct {
    Name    string  `json:"name"`
    Age     int     `json:"age"`
    Address Address `json:"address"`
}
```

The resulting JSON nests the address object under the `"address"` key.

## map[string]any — flexible unmarshaling

When you do not have a struct type ahead of time, unmarshal into `map[string]any`. Each JSON value becomes its natural Go counterpart: `string`, `float64`, `bool`, `[]any`, `map[string]any`, or `nil`.

```go
var m map[string]any
json.Unmarshal([]byte(`{"lang":"Go","version":1.22}`), &m)
fmt.Println(m["lang"])    // Go
fmt.Println(m["version"]) // 1.22  (float64)
```

export const encodingJsonCode = `package main

import (
\t"encoding/json"
\t"fmt"
)

type Address struct {
\tCity    string \`json:"city"\`
\tCountry string \`json:"country"\`
}

type User struct {
\tName    string  \`json:"name"\`
\tAge     int     \`json:"age"\`
\tEmail   string  \`json:"email,omitempty"\`
\tAddress Address \`json:"address"\`
}

func main() {
\t// Marshal a struct — Email is set, so it appears
\tu := User{
\t\tName:  "Alice",
\t\tAge:   30,
\t\tEmail: "alice@example.com",
\t\tAddress: Address{
\t\t\tCity:    "Bangkok",
\t\t\tCountry: "Thailand",
\t\t},
\t}
\tdata, err := json.Marshal(u)
\tif err != nil {
\t\tfmt.Println("marshal error:", err)
\t\treturn
\t}
\tfmt.Println(string(data))

\t// omitempty: Email is empty, so it is omitted
\tu2 := User{Name: "Bob", Age: 25, Address: Address{City: "London", Country: "UK"}}
\tdata2, _ := json.Marshal(u2)
\tfmt.Println(string(data2))

\t// Unmarshal back into a struct
\tvar result User
\terr = json.Unmarshal(data, &result)
\tif err != nil {
\t\tfmt.Println("unmarshal error:", err)
\t\treturn
\t}
\tfmt.Printf("Name: %s, City: %s\\n", result.Name, result.Address.City)

\t// map[string]any — flexible unmarshaling
\traw := \`{"lang":"Go","version":1.22,"stable":true}\`
\tvar m map[string]any
\t_ = json.Unmarshal([]byte(raw), &m)
\tfmt.Println(m["lang"], m["version"], m["stable"])
}`;

## encoding/json/v2 (Go 1.27)

Go 1.27 ships `encoding/json/v2` and its low-level companion `encoding/json/jsontext` as stable packages. Everything above still works: the v1 `encoding/json` API is unchanged, but it is now *implemented on top of v2*, so existing programs get the faster decoder for free (opt out with `GOEXPERIMENT=nojsonv2` if you hit a behavioural difference).

Import v2 when you want its API and stricter defaults:

export const jsonV2Code = `package main

import (
\t"encoding/json/v2"
\t"fmt"
\t"os"
)

type User struct {
\tName  string \`json:"name"\`
\tEmail string \`json:"email,omitempty"\`
\tAge   int    \`json:"age"\`
}

func main() {
\tu := User{Name: "Ada", Age: 36}

\tdata, err := json.Marshal(u) // same shape as v1 …
\tfmt.Println(string(data), err)

\tvar back User
\terr = json.Unmarshal(data, &back)
\tfmt.Printf("%+v %v\\n", back, err)

\tdata, _ = json.Marshal(map[string]int{"b": 2, "a": 1}, json.Deterministic(true)) // … plus variadic Options
\tfmt.Println(string(data))

\t_ = json.MarshalWrite(os.Stdout, u) // straight to an io.Writer
\tfmt.Println()

\t// stricter defaults: duplicate keys are rejected
\terr = json.Unmarshal([]byte(\`{"name":"A","name":"B"}\`), &back)
\tfmt.Println("duplicate key:", err)
}`;

`json.UnmarshalRead(r, &u)` is the mirror image of `MarshalWrite` — it decodes straight from an `io.Reader` such as `resp.Body`.

What is different from v1:

| Area | v1 `encoding/json` | v2 `encoding/json/v2` |
|------|--------------------|-----------------------|
| Invalid UTF-8 in strings | silently replaced | **rejected** |
| Duplicate object keys | last one wins | **rejected** |
| Field name matching | case-insensitive | exact match by default (`json.MatchCaseInsensitiveNames(true)` to relax) |
| Options | global `Encoder` setters | per-call `Options` values, composable |
| Embedding a struct's fields | anonymous field | `json:",embed"` tag (the old `inline` name was renamed) |
| Unmarshal speed | baseline | significantly faster; Marshal on par |

The stricter, case-sensitive name matching is easy to trip over silently. With `encoding/json/v2` imported, unmarshalling a lowercase key into an untagged field returns a `nil` error and leaves the field empty:

```go
type User struct {
	Name string // no tag
}

var u User
err := json.Unmarshal([]byte(`{"name":"Ada"}`), &u)
// v1: err == nil, u.Name == "Ada" — matched case-insensitively
// v2: err == nil, u.Name == ""    — no exact match, field left alone
```

v1 matched `name` to `Name` case-insensitively; v2 requires an exact match (or a `json:"name"` tag) by default. Always add explicit tags when moving code to v2.

`jsontext` is the streaming layer underneath: `jsontext.Decoder` and `jsontext.Encoder` walk a document as `Token`s and `Value`s while validating syntax, which is what you want for very large payloads or for rewriting JSON without decoding it into Go values.

```go
dec := jsontext.NewDecoder(r)
for {
    tok, err := dec.ReadToken()
    if err == io.EOF { break }
    // inspect tok.Kind(): '{', '}', '"', '0', …
}
```

Rule of thumb for 2026: keep v1 for existing code and for wire formats that tolerate sloppy input; start new services on v2 so malformed JSON fails loudly at the boundary.


## Trade-offs

| What you get | Benefit | Cost |
|---------|---------|------|
| json.Marshal/Unmarshal | Simple, no schema required | Reflection-based — 2-5x slower than a code-gen approach |
| Struct tags (`json:"name"`) | Control field names, omitempty | Checked only at runtime — no compile-time check that a tag is well-formed |
| json.Decoder (streaming) | Decode large or streamed JSON without loading it all into memory | A more complex API than Unmarshal |
| omitempty | Keeps zero values out of the JSON | 0, false, and "" all count as empty — this can surprise you |

## Common Misconceptions

- **json.Marshal/Unmarshal are goroutine-safe** — they are; but each `json.Decoder`/`Encoder` instance is not — never share one across goroutines.
- **Unexported fields get marshaled** — they do not; `encoding/json` ignores unexported fields regardless of any tag you write on them.
- **omitempty treats a pointer the same as its pointee** — `omitempty` on a `*T` checks the pointer itself: nil is omitted, non-nil is included, even when the value it points to is zero.
- **An `any` field in a struct always marshals as null** — it marshals according to the concrete type stored in the interface at runtime.

> 💡 Real-world example
>
> **Kubernetes API objects**: every Kubernetes resource (Pod, Deployment, Service) marshals and unmarshals through `encoding/json` — struct tags control every JSON key.
>
> **Go REST APIs**: `json.NewDecoder(r.Body).Decode(&req)` is the standard pattern nearly every Go API server uses to parse a request body.

<Callout title="Only exported fields are marshaled; tags control the JSON key names">
Fields that start with a lowercase letter are unexported and are completely invisible to `encoding/json` — they will never appear in the output and will never be populated during unmarshaling, regardless of what tag you write on them. Always make fields you want to serialize start with an uppercase letter. The `json:"name"` tag then controls the key name in the JSON output independently of the Go field name, so you can follow Go naming conventions (`UserID`) while producing clean JSON (`"user_id"`).
</Callout>
